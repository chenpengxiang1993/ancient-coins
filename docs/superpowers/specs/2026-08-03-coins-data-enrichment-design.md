# 钱币数据完整性核实与逐币完善 — 技术设计文档

日期：2026-08-03
状态：已批准（用户确认范围：外国铸币全面系统收录、版别深度细分、逐朝代确认节奏）

## 1. 需求概述

- **目标**：对 20 个朝代（`data/dynasties/0-19.json`）的 443 枚钱币做两项全面核实：
  - **任务一（种类完整性）**：逐朝代对照权威参考目录，核实钱币种类无遗漏；外国铸币（19.json）从现有 4 枚系统扩充为全面收录（安南/日本/朝鲜/琉球）。
  - **任务二（逐币数据核实）**：逐朝代逐枚核实所有字段准确性；完善版别体系（variantsTable）做到深度细分（勾笔、借笔、花穿、仰月等细节）；钱币特征必须包含旋读/直读描述。
- **背景**：项目为「中国古代钱币图鉴」，JSON-first 数据流水线，`data/dynasties/` 为唯一数据源。
- **约束**：AGENTS.md 强制——逐朝代按序执行、逐钱币按序处理、禁用批量脚本改数据、每朝代完成后运行 `pnpm run validate`、权威来源核实。

## 2. 方案设计

### 核心执行模型（三层）

```
① 只读审计脚本（scripts/audit-*.mjs）→ 驱动工作
     ├─ 朝代完整性核对：对比权威目录，列出缺失钱币
     ├─ 旋读/直读覆盖率：列出缺失描述的钱币
     └─ 版别表密度 + 字段空值检查
② 逐条手动完善（Edit 工具，严禁批量脚本改数据）
     └─ 逐朝代 → 逐钱币 → 逐字段，符合 AGENTS.md §2/§4
③ 每朝代完成后 pnpm run validate + 汇报确认
```

### 关键设计决策

**1. 旋读/直读分类口径**（应用到每枚钱币）：
- 圆形方孔钱 → 明确标注「四字**旋读**」或「四字**直读**」
- 先秦布币/刀币/蚁鼻钱/贝币（无圆孔环读）→ 用符合形制的读法描述（布币「面文自上而下直读」、刀币「自柄向首横读」等）
- 五铢/半两等两字钱 → 标注「面文左右横读（直读）」
- 位置：以 `featuresGroup.obverse` 面文句为主；涉及背文时在 `reverse` 同步标注

**2. 外国铸币子分组**：复用合并文件模式，`coin.dynasty` 字段用原子名（「安南钱币」「日本钱币」「朝鲜钱币」「琉球钱币」），前端可子分组展示。id 按全局 `{19}-{n}` 重编号。

**3. 完整性参考基线**：每朝代开工前产出该朝代《钱币清单核对表》（权威目录 vs 现有数据），缺失项逐枚补入。权威来源：AGENTS.md §9.1 所列《中国钱币大辞典》《中国古钱谱》《中国古钱目录》《历代古钱图说》。

**4. 新币图片**：无源图片的外国新币 `thumbnail`/`images.main` 留空（校验为提示级非错误），有图片目录的朝代补正路径。

**5. 审计脚本只读**：脚本仅输出差距报告，不改数据；数据变更全部走 Edit 工具，可追溯。

## 3. 影响范围

- **修改文件**：`data/dynasties/0-19.json`（全 20 个）
- **新增文件**：`scripts/audit-completeness.mjs`、`scripts/audit-features.mjs`（只读审计脚本）
- **不改动**：前端组件、类型、构建管线、既有校验脚本、既有生成脚本

```

P1: 逐朝代推进（每朝代内：完整性核对 → 缺失补入 → 逐币完善含旋读/直读 + 版别深度细分 → pnpm run validate → 汇报）
  朝代0 先秦 → 1 秦 → 2 汉 → 3 三国 → 4 两晋十六国 → 5 南朝 → 6 北朝

  → 14 西夏 → 15 元 → 16 明 → 17 清 → 18 花钱 → 19 外国（重点扩充）

```

## 5. 测试计划

- 数据结构：`pnpm run validate`（schema + 逻辑一致性）
- 完整性：audit 脚本输出缺失清单归零
- 旋读/直读：audit 脚本输出覆盖率 100%（含「无文/两字/先秦形制」合理豁免）
- 构建：`pnpm run build`
